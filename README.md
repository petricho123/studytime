# 작심삼일 · 공부의 시간 — 하늘색 통합 버전 2.0.0

기존 작심삼일 플래너와 공부시간 기록 앱을 한 안드로이드 앱으로 통합했습니다. 모든 화면·데이터 처리는 기기 안에서 이루어지며 인터넷 권한을 요청하지 않습니다.

## 기능

| 화면 | 기능 |
|---|---|
| 플래너 | 3일 기간·날짜 선택, 매일 루틴, 날짜별 계획, 추가·수정·삭제·완료 체크 |
| 공부 | 오늘 누적시간, 시작·일시정지·종료, 오늘 시간대별 기록 |
| 달력 | 이전·다음 달 이동, 월 총 공부시간, 날짜별 시간, 기록 추가·수정·삭제 |
| 설정 | 루틴 편집, 오늘 회차로, 리셋 이전 기록, 새로운 삼일 시작, 알림·배터리 설정, 백업·복원 |

- 루틴 항목은 한 회차에 공통이지만 **체크는 1·2·3일차 각각 독립**입니다.
- 이전·다음 3일 회차로 이동하거나 미래 계획을 미리 작성할 수 있습니다.
- 새 회차 루틴은 직전 작성 회차에서 독립적으로 복사하고 체크는 초기화합니다.
- 오늘부터 리셋하면 이전 과거·미래 회차는 읽기 전용 기록으로 보관합니다. 공부시간 기록은 지우지 않습니다.
- 상단 오늘 공부시간을 누르면 공부 화면으로 이동합니다.
- 앱 안의 플래너·공부·달력·설정 이동이나 계획 체크는 타이머를 멈추지 않습니다.

## 측정 규칙

| 행동 | 동작 |
|---|---|
| 공부 시작 | 오늘 누적시간에 이어서 측정 |
| 화면 끄기·자동 잠금 | 계속 기록 |
| 잠금화면만 반복 확인 | 계속 기록 |
| 잠금 해제 후 통합 앱 | 계속 기록 |
| 홈·다른 앱·최근 앱으로 이동 | 자동 일시정지 |
| 자동 정지 후 통합 앱 복귀 | 자동 재개 |
| 수동 일시정지·종료 | 사용자가 다시 시작할 때까지 정지 |
| 종료 후 같은 날 다시 시작 | 기존 오늘 시간에 누적 |
| 자정 경과 | 날짜별로 나누어 기록, 측정 유지 |
| 최근 앱에서 앱 쓸어 없애기 | 현재 측정 종료 |
| 프로세스 제거·강제 종료·재부팅 | 마지막 저장 기록 복원, 수동 재시작 |

이미 홈으로 나가서 멈춘 상태에서는 화면을 꺼도 정지 상태를 유지합니다. 알림을 누르면 공부 화면을 엽니다. 잠금화면·상단 알림창의 진행 중 알림에서 일시정지·종료할 수 있습니다.

휴대폰 제조사의 잠금·전원·최근 앱 이벤트 순서, 절전, 분할 화면, 잠금화면 카메라 등 특수 상황은 실제 기기에서 확인해야 합니다. 표준 안드로이드 알림이므로 시안과 실제 모양은 다를 수 있습니다. 별도의 잠금화면 위젯은 포함하지 않았습니다.

15초마다, 화면이 꺼질 때, 앱이 가려질 때, 정지·종료·수정 시 저장합니다. 깊은 절전 중에는 저장 주기가 지연될 수 있습니다. 프로세스가 살아 있으면 경과 시각으로 시간을 계속 계산합니다. 갑작스러운 프로세스 제거 후 확인되지 않은 시간을 자동으로 더하지 않습니다. 자정의 일별 합계는 날짜 경계로 계산하지만 절전 중 알림 표시 갱신은 화면을 켤 때까지 지연될 수 있습니다.

## 기존 앱 위에 업데이트

- 기존 플래너와 같은 앱 ID: `com.petricho.threedays`.
- 기존 WebView 주소 `https://planner.local/`와 저장 키 `three-day-planner-v1`을 그대로 사용합니다.
- 버전 코드는 2, 표시 버전은 2.0.0입니다.
- `petricho123/three-day-planner` 현재 저장소에서 사용하는 **공개 개발용 서명 키**를 재사용합니다. 이 키로 설치한 기존 플래너라면 정상 업데이트 시 계획·완료 체크·보관 기록이 유지되도록 구성했습니다.
- 다른 키로 설치했거나 개인 서명을 쓰고 있다면 같은 키로 다시 빌드해야 합니다. 설치가 안 된다고 기존 앱부터 삭제하지 마세요. 앱 삭제·데이터 삭제는 기존 기록을 지울 수 있습니다.
- 개인 키를 쓰는 경우 이전과 동일한 `PLANNER_KEYSTORE_*`/`PLANNER_KEY_*` Secrets를 사용하세요.
- 개발용 공개 키는 개인 테스트·호환 업데이트 목적입니다. 정식 배포에는 본인 소유의 비공개 키가 필요합니다.

별도로 설치된 공부시간 앱(`kr.studytime.app`)의 내부 기록은 안드로이드 앱 격리 때문에 자동으로 읽을 수 없습니다. 지원되는 JSON 기록 파일이 있다면 설정의 가져오기를 사용할 수 있습니다. 기존 공부 앱에 내보내기 기능이 없다면 별도의 내보내기 업데이트가 먼저 필요합니다.

## 백업·복원

설정 → 전체 기록 백업 파일 저장에서 플래너·공부 기록이 포함된 JSON 파일을 저장할 수 있습니다.

- 통합 앱 전체 백업: 확인 후 현재 플래너와 공부 기록을 백업 내용으로 교체합니다.
- 공부 기록 JSON(`version:1`, `records` 배열): 현재 공부 기록에 추가합니다. 겹치는 시간은 합계에서 중복 계산하지 않습니다.
- 가져오기 전에 현재 기록을 먼저 백업하세요.
- 가져오기와 공부 기록 편집은 타이머를 일시정지한 상태에서 사용합니다.
- 4MB 이하 JSON을 지원합니다. 파일 선택기에 나갔다 돌아오는 동작에는 일반적인 앱 이탈 규칙이 적용됩니다.
- 앱 삭제 전에는 백업 파일을 앱 밖의 안전한 위치에 보관하세요.

## GitHub에서 빌드 — 컴퓨터로 폴더를 올리는 경우

프로젝트 폴더의 **내용 전체**를 저장소 루트에 올립니다. `.github`와 `signing/development.keystore`도 포함해야 합니다. 처음부터 새 저장소에서 빌드해도 APK는 같은 앱 ID를 사용합니다.

저장소 최상위에 `app/`, `gradle/`, `tests/`, `signing/`, `.github/`, `package-lock.json`, `build.gradle`, `settings.gradle`이 있어야 합니다.

Actions → **Build Integrated APK** → Run workflow. `main`/`master`에 업로드하면 자동 실행도 됩니다. 초록색 체크로 끝나면 실행 하단 **Artifacts → three-day-study-apk**를 내려받고 압축을 풀어 `app-debug.apk`를 설치합니다.

기존 저장소 소스에 덮어 올리는 경우 다른 앱의 Java 패키지나 오래된 workflow를 함께 남기지 않도록 주의하세요. 모바일에서는 아래 ZIP 방식이 편리합니다.

## GitHub에서 빌드 — 안드로이드에서 ZIP을 올리는 경우

프로젝트 폴더 바깥에 함께 들어 있는 `START-HERE.md`와 `UPLOAD-BUILD.yml`을 참고하세요. `three-day-study-v2.0.0.zip`을 저장소에 그대로 올리고, `.github/workflows/integrated-zip.yml`에 `UPLOAD-BUILD.yml` 내용을 붙여 넣으면 됩니다. 압축 해제와 빌드는 분리된 임시 폴더에서 실행하므로 저장소에 예전 소스가 남아 있어도 섞이지 않습니다.

## 빌드 환경

- Android 8.0 이상, compile/target SDK 35
- Java 17, Gradle 8.11.1, Android Gradle Plugin 8.9.2
- Gradle Wrapper 포함 (다운로드 SHA-256 검증)
- JavaScript 테스트: Node 22, `npm ci --ignore-scripts`
- 앱 런타임 외부 라이브러리 없음, npm 의존성은 테스트 전용
- 네트워크·접근성·다른 앱 사용 기록 권한 없음
- 화면 꺼짐 상태의 사용자 시작 타이머에 `specialUse` 전경 서비스 사용

```sh
npm ci --ignore-scripts
node --test tests/*.test.cjs
bash tests/run.sh
./gradlew :app:assembleDebug :app:lintDebug
```

Google Play 등록은 별도 배포 작업입니다. 현재 파일은 개인용 APK 빌드·설치를 위한 프로젝트입니다.

## 개인 서명 키 설정 (선택)

현재 저장소는 기존 플래너와 동일한 개발용 키로 기본 빌드합니다. 개인 키를 사용하는 경우 다음 Secrets를 모두 설정하세요.

| Secret | 내용 |
|---|---|
| `PLANNER_KEYSTORE_BASE64` | 키 파일의 Base64 |
| `PLANNER_KEYSTORE_PASSWORD` | 키 저장소 암호 |
| `PLANNER_KEY_ALIAS` | 키 별칭 |
| `PLANNER_KEY_PASSWORD` | 해당 키 암호 |

개인 키 파일과 암호는 공개 저장소에 올리지 마세요. 기존 설치의 서명 키를 바꾸면 그대로 업데이트할 수 없습니다.

## 구현 구조

기존 `core.js`와 데이터 형식은 유지했습니다. `app.js`는 날짜별 탭 형태의 플래너 UI, `study.js`는 공부·달력·설정 UI입니다. Java `MainActivity`가 APK에 포함된 내부 화면만 로드하고 네이티브 타이머와 연결합니다. 외부 탐색·iframe·통신은 차단합니다. `StudyEngine`이 날짜별 합계와 구간 중복 제거를 담당하고 `TimerService`가 알림과 화면 잠금 상태를 관리합니다.

## 실기기에서 확인할 항목

1. 시작 → 플래너 체크·달력 이동: 계속 누적.
2. 1일차 루틴 체크 → 2·3일차: 미완료 유지.
3. 종료 → 다시 시작: 오늘 누적 유지.
4. 화면 끄고 2분 → 잠금화면 반복 확인: 계속 누적.
5. 홈·다른 앱에서 1분 → 복귀: 그 1분 제외, 자동 재개.
6. 홈 직후 화면 끄기: 정지 유지.
7. 수동 정지·종료 후 재진입: 자동 재개 안 함.
8. 잠금화면 알림에서 일시정지·종료, 알림 누르면 공부 화면.
9. 이전·다음 달, 자정 전후 일별 합계.
10. 기록 수정·삭제와 전체 백업·복원.
11. 앱 강제 종료 후 마지막 저장 기록 복원 안내.
12. 장시간 화면 꺼짐·절전 모드 측정. 필요하면 배터리를 ‘제한 없음’으로 설정.

자동화 테스트와 브라우저 UI 확인은 실제 안드로이드 잠금·절전·업데이트 데이터 유지 검증을 대신하지 않습니다.

공식 참고: [WebView](https://developer.android.com/develop/ui/views/layout/webapps/webview), [Foreground service types](https://developer.android.com/develop/background-work/services/fgs/service-types), [Activity lifecycle](https://developer.android.com/guide/components/activities/activity-lifecycle).

## 맥북용 PWA

1. GitHub 저장소의 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정합니다.
2. **Actions → Build and deploy PWA → Run workflow**에서 `main`을 선택합니다. 이후 PWA 소스를 `main`에 반영하면 자동 배포됩니다.
3. 배포된 주소를 맥북 Safari에서 열고 **파일 → Dock에 추가**를 누릅니다(macOS Sonoma 14 이상).

**공부 → 탁상시계**에서 현재 시각과 오늘 누적 공부시간을 볼 수 있습니다. 시계 크기는 창 크기에 맞춰 바뀌고, 전체 화면 버튼이나 macOS 창 제어로 확대할 수 있습니다. 브라우저가 허용하는 경우 탁상시계가 표시되는 동안 화면이 계속 켜집니다.

공부 기록과 플래너는 해당 웹 앱에 저장됩니다. 안드로이드의 **설정 → 전체 기록 백업 파일 저장**으로 만든 JSON은 웹 앱의 **설정 → 백업·공부 기록 가져오기**에서 복원할 수 있습니다. 첫 로딩을 완료한 뒤에는 오프라인으로 다시 열 수 있습니다.

로컬에서 확인하려면 `node pwa/build.mjs /tmp/studytime-pwa`를 실행하고 `python3 -m http.server 8000 --directory /tmp/studytime-pwa`로 연 뒤 `http://localhost:8000`에 접속합니다.
